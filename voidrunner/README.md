# VOIDRUNNER

A 3D sci-fi corridor runner for phones, built with three.js. One folder, no
build step, no dependencies to install, no server to run. Open `index.html`
over HTTP and play.

**No ads. No tracking. No purchases. No network calls at runtime.** Everything
you earn is stored in `localStorage` on your own device, and after one visit the
whole game runs offline.

---

## Play

Serve the folder and open it. Any static server will do:

```sh
cd voidrunner
python3 -m http.server 8000     # then open http://localhost:8000
```

It has to be served over HTTP rather than opened as a `file://` URL, because the
game is made of ES modules.

On a phone, use **Add to Home Screen** — it is a PWA, so it installs, launches
fullscreen and works with the radio off.

### Controls

| | |
|---|---|
| **Steer** | Drag anywhere. The ship follows how far your thumb moves, not where you touched, so your hand never covers the ship and you can re-grip mid-run. `Settings → Steering → DIRECT` switches to absolute positioning. |
| **Overdrive** | Tap the round button, or put a second finger anywhere on the screen. |
| **Keyboard** | Arrows / WASD to steer, space for overdrive, P or Esc to pause. |

### How it plays

Fly forward down an endless corridor and thread the gaps.

* **Graze.** Squeezing past a hazard without touching it is the whole game.
  Each near-miss fills the heat bar; filling it steps your multiplier up, and
  letting it drain steps it back down. Passing *very* close scores double and
  is called out as PERFECT.
* **Overdrive.** Grazes charge it, cells trickle into it. When it is full you
  get five seconds of invulnerable, faster, triple-score flight that smashes
  every hazard in front of you.
* **Shields.** Each hit costs one. Blue rings give one back. Zero ends the run.
* **Sectors.** Every 1500 m the corridor changes hands — new palette, new
  hazard mix, faster and tighter. Six sectors, then it loops at a higher
  difficulty tier and keeps going.
* **Cells and contracts.** Cells buy ships in the hangar. Three rolling
  contracts give you something specific to chase, and reroll as you clear them.

## How it is built

```
voidrunner/
  index.html            markup for every screen
  styles.css            UI shell; accent colours are CSS vars the game rewrites per sector
  manifest.webmanifest  PWA manifest
  sw.js                 precache service worker
  vendor/               three.js r185 (MIT), vendored so nothing is fetched at runtime
  icons/                generated by tools/make-icons.mjs
  tools/make-icons.mjs  procedural PNG icon generator (pure Node, no image libs)
  src/
    main.js       boot, screen stack, frame loop
    game.js       the run: simulation, collision, camera, scoring
    config.js     every tunable that defines the feel
    path.js       the corridor centreline
    spawner.js    the director - decides what appears and where
    hazards.js    the nine hazard kinds and their collision maths
    pickups.js    cells, shields, charge
    world.js      rings, rails, megastructure, stars, backdrop
    ship.js       procedural ship mesh and flight model
    ships.js      the hangar roster
    fx.js         particles, shockwaves, screen shake
    audio.js      the entire soundtrack and every sound effect, synthesised
    input.js      one-thumb steering
    hud.js        in-run HUD
    save.js       localStorage, records, contracts
    geom.js       shared geometry builders
    textures.js   every texture, drawn on a canvas at runtime
    util.js       maths helpers and a seeded PRNG
```

There are four ideas worth knowing about if you want to change anything.

**Tube space.** Nothing is authored in world coordinates. A point is an
`(x, y)` offset in the corridor's cross-section at a distance `Z` along it, and
`path.js` turns that into a world position. The corridor centreline is an
analytic function of `Z` rather than a baked spline, which is why the world can
be infinite with no seams and no memory growth — and why rendered `z` can be
rebased every 10 km to keep float32 precision tight without the corridor
changing shape.

**Collision is 2-D signed distance.** Every hazard implements `sdf(h, x, y)`
returning the signed distance from a cross-section point to its solid part. No
raycasts, no physics engine. Collision is `sd < SHIP_R`; a near-miss is
`sd < SHIP_R + GRAZE_R`. Forward motion is substepped so nothing tunnels at
130 units a second. Grazes are scored per hazard — the closest approach is
tracked and cashed in the instant you pass — because at that speed you are only
beside a hazard for about 70 milliseconds.

**The flow line.** `spawner.js` maintains a point in the cross-section that
wanders no faster than the ship can chase it, and every hazard is *generated
around* that point: gates aim their gap at it, spinners phase their blades so
the opening faces it on arrival, bars leave it a lane, blocks sit on the far
side. Cells are strung along it. That is what makes a procedural runner feel
authored — there is always a line, and the line is always makeable, but you
have to read it in time. A bot that flies the line exactly survives roughly
60 km per six-minute soak.

Because rotating hazards are phased against *when you will arrive*, anything
that changes your speed unexpectedly would desynchronise them. Overdrive does
exactly that, so starting and ending a burst re-aims everything still ahead.

**Nothing is loaded.** Textures are drawn on a `<canvas>` at startup, geometry
is built from primitives, icons are generated by a Node script, and the music
and sound effects are synthesised with WebAudio — a lookahead sequencer over
kick/hat/snare/bass/arp/pad voices whose scale, tempo and brightness come from
the current sector, and which thickens as your multiplier climbs. The only
asset in the repository is three.js itself.

### Performance

Roughly 50–75 draw calls and ~30k triangles in a typical frame, whatever the
sector, because rings, rails, structures, hazards, pickups and particles are all
instanced or pooled. The renderer watches frame time and steps device pixel
ratio and effect density down on slow hardware; `Settings → Graphics` pins it
if you would rather choose.

### Regenerating the icons

```sh
node tools/make-icons.mjs
```

### Tuning

`src/config.js` holds every constant that defines the feel — speed ramp,
handling, camera lag, graze radius, scoring, spawn density. `src/zones.js` holds
the six sectors: palette, hazard weights, tempo. Change a number, reload, play.
